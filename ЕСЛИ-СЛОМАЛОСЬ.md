# Если сломалось

Спокойно. Сломать здесь нечего: ваши рабочие папки мост не трогает, а сам он ставится
заново за пять минут. Ниже — по симптомам.

## Первое, что стоит сделать всегда

```bash
.venv/bin/python scripts/selftest.py --name default
```

Самопроверка смотрит настройки, права на файл с токеном, нейросеть и дорогу до
мессенджера и отвечает списком: что в порядке, что нет и что с этим делать.
Непонятно — покажите этот вывод целиком своей нейросети, она разберётся.

---

## «Бот молчит»

Три причины, и они идут именно в таком порядке.

**1. Вас нет в списке своих.** Так и задумано: пока список пуст, мост не отвечает никому,
включая хозяина. Напишите ему что-нибудь, а потом посмотрите журнал:

```bash
sqlite3 ~/.most/default/most.db "select at, channel, user_id, text from journal where kind='stranger' order by id desc limit 5"
```

Увидели там свой стук — значит, id в настройках другой. Возьмите из этой строки и впишите
в `allowlist`, после этого перезапустите мост.

**2. Токен не тот.** Посмотрите, что мост говорит в журнале:

```bash
journalctl -u most@default -n 30 --no-pager
```

Строка «Telegram не признал токен» значит ровно это: бот не заведён или токен перевыпущен.
Вернитесь к отцу ботов (`@BotFather`), возьмите токен заново, впишите в `config.yaml`,
перезапустите: `sudo systemctl restart most@default`.

**3. Бот занят другим слушателем.** Строка «на этого бота уже кто-то подписан» значит, что
где-то запущен второй мост с тем же токеном или боту поставили вебхук. Один бот — один
слушатель, второго выключаем:

```bash
systemctl list-units 'most@*'          # кто ещё запущен
sudo systemctl stop most@<лишний>
```

## «Работало, пока не перезагрузился»

Юнит не был включён на автозапуск. Включается один раз:

```bash
sudo systemctl enable --now most@default
```

Проверка честная: `sudo reboot`, через минуту напишите боту. Ответил — всё на месте.

## «Мост отвечает, а нейросеть нет»

Скорее всего, `claude` не видит вашего входа. Проверьте руками от того же пользователя,
от которого работает мост:

```bash
claude --version
cd ~/projects/<папка> && claude -p "скажи одно слово"
```

Просит войти — войдите под своей подпиской и запустите мост снова. Ключи API здесь ни при
чём: мост их не использует.

## «Ответ обрывается на полуслове»

Длинный ответ мост режет на куски под предел мессенджера (4096 символов в Telegram,
4000 в Max) и шлёт подряд. Пришёл один кусок вместо трёх — посмотрите журнал работы:

```bash
ls -t ~/.most/default/jobs | head -3
cat ~/.most/default/jobs/<id>/err.log
```

## «Задача идёт и не заканчивается»

У работы есть предел времени, по умолчанию пятнадцать минут. Он в `config.yaml`,
поле `timeout_sec`. Мост остановит такую работу и честно скажет об этом в чат.
Если задача действительно большая — разбейте её на части поменьше.

## «Max не отвечает, Telegram работает»

У Max свои сертификаты: они выданы российским удостоверяющим центром, которого нет
в стандартном наборе. Связка лежит в пакете (`certs/max_ca_bundle.pem`) и подставляется
сама. Если файл потерялся при копировании — верните его на место, иначе запросы будут
падать на проверке сертификата.

## «Хочу посмотреть, что вообще происходило»

```bash
sqlite3 ~/.most/default/most.db "select started_at, state, prompt_head from jobs order by started_at desc limit 10"
sqlite3 ~/.most/default/most.db "select at, kind, channel, text from journal order by id desc limit 20"
ls -t ~/.most/default/jobs | head            # журналы работ папками
```

## «Хочу начать с чистого листа»

```bash
sudo systemctl stop most@default
mv ~/.most/default/most.db ~/.most/default/most.db.staraya
sudo systemctl start most@default
```

Настройки и рабочие папки останутся на месте: пропадут только связки чатов с папками
и журнал стуков.
