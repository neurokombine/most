# Если сломалось

Спокойно. Сломать здесь нечего: ваши рабочие папки мост не трогает, а сам он ставится
заново за пять минут. Ниже — по симптомам.

## Первое, что стоит сделать всегда

```bash
.venv/bin/python scripts/selftest.py --name default
```

Самопроверка смотрит настройки, права на файл с токеном, нейросеть и дорогу до
мессенджера и отвечает списком: что в порядке, что нет и что с этим делать.
Непонятно — покажите этот вывод целиком своей нейросети, она разберётся.

---

## «Бот молчит»

Три причины, и они идут именно в таком порядке.

**1. Вас нет в списке своих.** Так и задумано: пока список пуст, мост не отвечает никому,
включая хозяина. Напишите ему что-нибудь, а потом посмотрите журнал:

```bash
sqlite3 ~/.most/default/most.db "select at, channel, user_id, text from journal where kind='stranger' order by id desc limit 5"
```

Увидели там свой стук — значит, id в настройках другой. Возьмите из этой строки и впишите
в `allowlist`, после этого перезапустите мост.

**2. Токен не тот.** Посмотрите, что мост говорит в журнале:

```bash
journalctl -u most@default -n 30 --no-pager
```

Строка «Telegram не признал токен» значит ровно это: бот не заведён или токен перевыпущен.
Вернитесь к отцу ботов (`@BotFather`), возьмите токен заново, впишите в `config.yaml`,
перезапустите: `sudo systemctl restart most@default`.

**3. Бот занят другим слушателем.** Строка «на этого бота уже кто-то подписан» значит, что
где-то запущен второй мост с тем же токеном или боту поставили вебхук. Один бот — один
слушатель, второго выключаем:

```bash
systemctl list-units 'most@*'          # кто ещё запущен
sudo systemctl stop most@<лишний>
```

## «Работало, пока не перезагрузился»

Юнит не был включён на автозапуск. Включается один раз:

```bash
sudo systemctl enable --now most@default
```

Проверка честная: `sudo reboot`, через минуту напишите боту. Ответил — всё на месте.

## «Мост отвечает, а нейросеть нет»

Скорее всего, `claude` не видит вашего входа. Проверьте руками от того же пользователя,
от которого работает мост:

```bash
claude --version
cd ~/projects/<папка> && claude -p "скажи одно слово"
```

Просит войти — войдите под своей подпиской и запустите мост снова. Ключи API здесь ни при
чём: мост их не использует.

## «Ответ обрывается на полуслове»

Длинный ответ мост режет на куски под предел мессенджера (4096 символов в Telegram,
4000 в Max) и шлёт подряд. Пришёл один кусок вместо трёх — посмотрите журнал работы:

```bash
ls -t ~/.most/default/jobs | head -3
cat ~/.most/default/jobs/<id>/err.log
```

## «Задача идёт и не заканчивается»

Напишите в чат **«стоп»** — мост погасит работу и скажет, что успела сделать.
Если ждать некогда и в следующий раз, уменьшите бюджет времени: раздел `executor`,
поле `timeout_sec` (по умолчанию 900 секунд, то есть пятнадцать минут). По бюджету
мост останавливает работу сам и честно говорит об этом в чат.

## «Он отвечает „я ещё работаю над прошлым“, а я ничего не просил»

Значит, предыдущая задача ещё идёт: на одну связку — одна работа за раз, иначе
в одной папке окажутся две нейросети сразу и они переспорят друг друга. Варианта два:
подождать или написать «стоп».

## «Пишет „прошлый разговор не нашёлся“»

Ключ разговора у мессенджера есть, а самой истории на машине не осталось: её вычистили,
переставили систему или разговор заводился под другим пользователем. Мост в этом случае
начинает новый разговор и говорит об этом вслух. Договорённости («работаем по августу»,
«формат такой-то») придётся повторить — это не поломка.

## «Она отчиталась „сделано“, а сделано ли?»

Спросите **«покажи, что получилось»**. Мост посмотрит папку проекта сам, без нейросети,
и покажет файлы, изменившиеся после начала последней работы. Пусто — значит, нейросеть
рассказала о работе, которой не было. Это не редкость и это надо проверять.

## «Прислал файл, а он никуда не лёг»

Сначала спросите в чате: **«куда ты положила то, что я прислала»** — мост назовёт полный
путь. Молчит или отвечает, что ничего не было, — смотрите по порядку:

**1. Файл больше, чем пускает мессенджер.** Телеграм отдаёт боту файлы **до 20 МБ**,
и это их предел, а не настройка моста. На большой файл мост отвечает честно: столько
через чат не проходит. Положите его на сервер из окна редактора — мышкой — и напишите
в чат, что с ним сделать.

**2. Голосовое вместо файла.** Голосовые мост пока не слышит: это следующий этап.
Запись, присланная файлом (документом), забирается как обычный файл.

**3. Не та папка.** Файл ложится в «входящие» **внутри текущей рабочей папки**. Если вы
перед этим сказали «работаем с другой папкой», ищите там. Какая папка текущая — спросите
«покажи проекты», она помечена.

```bash
ls -lt ~/projects/*/входящие | head
sqlite3 ~/.most/default/most.db "select at, kind, text from journal where kind='error' order by id desc limit 5"
```

## «Попросил файл, а он не пришёл»

**Мост отвечает «таких несколько».** Он нашёл больше одного похожего и не стал гадать.
Скажите точнее — можно частью имени: «пришли мне отчёт сентябрь».

**Мост отвечает «не нашла» и показывает список.** Значит, файла с таким именем в рабочей
папке нет. Проверьте, в той ли вы папке (см. выше) и не лежит ли он во вложенной —
мост ищет и в них, но не заглядывает в служебные (`.git`, `node_modules`, venv).

**Мост отвечает «файл весит столько-то, а телеграм пропускает 50 МБ»** и даёт путь.
Это не поломка: забирайте файл из окна редактора, мышкой.

**Пришло «отправить не вышло» с путём.** Файл на месте, не дошла отправка: чаще всего
сеть. Попробуйте ещё раз. Повторяется — посмотрите журнал:

```bash
sqlite3 ~/.most/default/most.db "select at, channel, text from journal where kind='error' order by id desc limit 10"
```

**Сказали «отдай», а мост просит имя.** Значит, в прошлом ответе нейросеть файла не
назвала — или назвала, но не тронула его на диске. Мост отдаёт только то, что правда
изменилось после начала работы: «сохранила в отчёт.xlsx» без самого файла для него
не доказательство. Скажите «пришли мне <имя>» — найдёт по части имени.

## «Голосовое не поняла»

Мост отвечает на голосовое одной из четырёх фраз, и каждая значит своё.

**«Голос у меня не настроен».** Распознавание не поставлено — это нормальное состояние
моста по умолчанию, голос ставится отдельно:

```bash
bash scripts/setup.sh --voice          # две библиотеки и модели, минут пять
.venv/bin/python scripts/selftest.py   # строка про голос покажет, что получилось
sudo systemctl restart most@default
```

Сама запись при этом не пропала: она лежит в `~/projects/<папка>/входящие/голос/`.

**«Слов не разобрала».** Запись дошла, но в ней тихо или много шума. Наговорите ближе
к микрофону, без улицы и музыки. Повторяется на всех записях — проверьте, что модель
скачалась целиком:

```bash
.venv/bin/python scripts/selftest.py --name default | grep -i голос
du -sh ~/.most/models/faster-whisper           # «small» — около 500 МБ
```

**«Запись длиннее трёх минут».** Это не поломка, а предел: длинную запись сервер будет
жевать минутами, и всё это время мост молчит для остальных. Наговорите покороче
или напишите текстом. Предел меняется в настройках (`voice.max_seconds`), но помните,
чем платите: тридцать секунд речи — это двадцать секунд ожидания на четырёх ядрах.

**Мост долго молчит после голосового, а потом отвечает.** Так и работает: сначала идёт
расшифровка, и только потом «услышала: …». Если ждать приходится больше минуты на
коротких записях — машине тяжело. Поставьте модель полегче:

```yaml
voice:
  model: base        # вдвое быстрее и вдвое легче, но чаще путает слова
```

**Ответ приходит текстом, хотя просили голосом.** Значит, `piper` или его голос
не поставлены — мост говорит об этом один раз и дальше не бубнит. Лечится тем же
`bash scripts/setup.sh --voice`. Если ответ приходит аудио-файлом вместо привычного
голосового кружка — на сервере нет `ffmpeg`: `sudo apt install -y ffmpeg`.

## «Утром ничего не пришло»

**Сначала одна фраза, прямо в чат:**

> покажи, что ты запускала ночью и чем закончилось

Мост ответит списком прогонов за сутки: когда, сколько шли, чем кончились. Дальше
причин ровно три, и ответ обычно виден прямо в этом списке.

**1. Задачи в расписании нет — или она выключена.** Самое частое: фразу мост не разобрал
и переспросил, а ответ потерялся в чате. Спросите:

> покажи, какое задание стоит на расписании сейчас

Пусто — поставьте заново, обязательно со временем: «каждое утро в 7:30 собирай сводку
по моему делу». Стоит, но помечено «выключена» — скажите «включи задачу 1».

**2. Мост ночью не работал.** Сервер перезагружали, юнит не был включён на автозапуск,
машину выключал хостер. В списке прогонов такая ночь выглядит строкой «пропустила».
Проверьте службу:

```bash
systemctl status most@default
sudo systemctl enable --now most@default     # чтобы поднимался сам после перезагрузки
```

Опоздание меньше шести часов мост догоняет сам, одним запуском. Больше — не догоняет
нарочно: пять пропущенных дней подряд в девять утра съедят дневной лимит.

**3. Работа шла, но не вышла.** В списке она будет с пометкой «не вышло». Причина обычно
там же: кончился дневной лимит подписки (тот самый «утром лимит на нуле»), нейросеть не
нашла файл, папку переименовали. Скажите ей в чат «покажи журнал моста» — она посмотрит
сама. И проверьте, не стоит ли у вас три ночные задачи вместо одной.

**Сводка пришла, но вчерашняя.** Значит, мост работает, а задача не отработала: смотрите
причину 1 и 3. Проверить руками, не дожидаясь утра:

> запусти задачу 1 сейчас

Отчёт придёт через минуту — и будет видно, где спотыкается.

## «Время не то: пишет 7:30, а приходит в 9:30»

Мост считает время **московским** — и своё, и в задачах. Часы самой машины он не
спрашивает: у хостера в Амстердаме они отстают на два часа. Если вам нужна другая зона,
впишите её в настройки одной строкой:

```yaml
timezone: "Asia/Novosibirsk"
```

Мост не знает такой зоны — скажет об этом в журнале и останется на московской.
А вот отчёты приходят раньше или позже на постоянную величину — значит, зона всё-таки
подменилась: посмотрите `journalctl -u most@default | grep пояс`.

## «Max не отвечает, Telegram работает»

У Max свои сертификаты: они выданы российским удостоверяющим центром, которого нет
в стандартном наборе. Связка лежит в пакете (`certs/max_ca_bundle.pem`) и подставляется
сама. Если файл потерялся при копировании — верните его на место, иначе запросы будут
падать на проверке сертификата.

## «Хочу посмотреть, что вообще происходило»

Проще всего — прямо в чате: **«что ты делала»** покажет последние пять работ этого чата:
когда, сколько шли, чем кончились. Подробнее — в базе:

```bash
sqlite3 ~/.most/default/most.db "select started_at, state, prompt_head from jobs order by started_at desc limit 10"
sqlite3 ~/.most/default/most.db "select at, kind, channel, text from journal order by id desc limit 20"
sqlite3 ~/.most/default/most.db "select id, spec, enabled, next_run_at, last_status from schedule"
ls -t ~/.most/default/jobs | head            # журналы работ папками
```

## «Хочу начать с чистого листа»

```bash
sudo systemctl stop most@default
mv ~/.most/default/most.db ~/.most/default/most.db.staraya
sudo systemctl start most@default
```

Настройки и рабочие папки останутся на месте: пропадут только связки чатов с папками
и журнал стуков.
